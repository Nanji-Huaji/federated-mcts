# Root-judge pilot protocol (root4-v1)

Frozen prior to scoring. Purpose: a **new inference** check of whether a larger instruction-tuned model picks a reachable state better on the same small first-layer candidate pool. It is not a full solver run, cloud experiment, model-selection step on the test set, or a replication of the historic 32B/DeepSeek route.

- All 20 prespecified repository validation-pilot IDs, one root per puzzle. No outcome-based exclusion. Pull the **already generated** first-step candidates from the hash-pinned 200-task B0 archive; check the move consumes the stated inputs once each and gives the stated nonnegative integer remaining triple. Merge identical sorted remaining triples. Order by SHA-256 of `1729|task_id|comma-joined-triple`, take first four; no votes or solvability labels used. The prepared JSON SHA-256 is `54a574ef35cfe3f42dec8f8719ac1265c548b5d31063f30a1f83863519fa51be`.
- Each judge (cached original Qwen2.5-7B-Instruct and 32B-Instruct with immutable snapshot IDs) sees the same four triples and instructions, no original prompt, votes or oracle labels. Primary: hash order. Order sensitivity: reverse all four; no picking the better order. Deterministic restricted-choice next-token forward pass on CPU, taking raw logits for exactly `A,B,C,D`; no free-text decoding, sampling, thought generation or new branches. Stable lower display index for equal scores.
- Only after scores are saved for both judges, use exact nonnegative-integer/whole-division reachability to label each triple; primary endpoint: top-1 viable on all 20. Also top-2, same winner after reversal, and paired membership. The denominator for conditional coverage excludes only pools with no viable option; report the unconditional result and coverage ceiling as well. Exact chance control: choose one/two distinct options uniformly without replacement conditional on the same pool, no simulation.
- Each model sequentially receives 40 prompts (two orders per puzzle, not 40 independent puzzles), threads capped and no hosted model requests; wall time is single-host CPU time under current load, not an estimate of cloud deployment costs. Scores/IDs are saved; a zero difference, poorer larger model or high order sensitivity will be reported as such.
