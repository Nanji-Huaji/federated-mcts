# Game24：同一批 30 题的历史轨迹复判

**结论。** 按每题最后保留的十条轨迹中至少一条验算通过计，全云解出 26 题，边端生成/云端评估解出 23 题，后者加首层云端热启动解出 25 题。热启动比全云少解一题，历史云端费用字段低 39.45%；没有据此证明精度等同或总成本更低。本次只运行了本地验算与统计，没有生成新轨迹。

## 对照与判分

所用三对原始输出与用量记录的相对路径、字节数和 SHA-256 见[输入清单](summary.json)。每组恰有 [Game24 数据](<../../../src/tot/data/24/24.csv#L902-L931>)零基索引 900–929（CSV Rank 901–930）。各层输入逐题与 CSV 核对。C = 全云 DeepSeek-V3；S = Qwen2.5-32B-Instruct 生成、DeepSeek-V3 评估；W = 同 S，但首层改云生成。角色沿用归档对应关系，与[旧分派代码](<../../../src/tot/methods/bfs.py#L457-L486>)一致；日志的模型用量可核对，没有逐请求角色清单。标称温度 0.7、propose / value / greedy、深三层、保留至多十条；相同标称参数不等于相同实耗。

末层按原序取顶层字段 `ys`；已核对它与 `steps[-1].select_new_ys` 完全一致，且逐层重建的稳定降序前十与历史选择相同。JSON 解码后直接逐行全匹配 `a op b = c (left: …)`，只去一个可选结尾换行。三组末层候选共 4,410 行，都是该格式的非负整数写法。每条从题面四数开始，必须恰有三步：每步按重数取走两个操作数，按精确有理数验四则等式与整个剩余多重集，最后只余 24。除零、算错、伪造余数、提前结束均不通过；不修日志，不补步骤，不运行符号搜索。裁判支持精确分数，不代表历史搜索生成过分数。全云 9 条已选链只有两步，均留作失败。

以题为单位等概率有放回抽取 30 对，按每题 A−B 为 +1/−1/0 的经验频数精确枚举配对 bootstrap 分布，取 2.5% 与 97.5% 分位；没有独立抽两组或抽 900 个槽位。这一小段题不是随机盲测，也没有独立运行重复，区间不能支持非劣效或热启动因果结论。

**对末层选择敏感吗？** W 对 S 的任一口径净多两题；若只交首条，两组都解出 13 题，但仅 W 与仅 S 各有 5 题。检查全部末层候选（不只看前十）：C、S、W 各有 103/480、77/513、86/482 条合法链，覆盖的 26、23、25 题已全部保有合法解，固定该池只改末层前十排序不能多解一题。若只交一条且仅打乱最高分间的顺序，三组分别有 23、25、27 题出现最高分并列。按题在最高分槽中均匀选一个，解题数期望仅为 3.47、3.28、3.19（原顺序为 14、13、13）。这是现成候选及分数的敏感性分析，不是实测随机策略，也不代表只生成一条的花费。
