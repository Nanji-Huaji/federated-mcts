# Game24：同 148 题的完整解重复采样与全云树搜索

**摘要。** 对历史 DeepSeek-V3 归档离线复判。每题依次取 1、3、10 份直接生成的完整答复，至少一份解对的题数为 **77、106、130 / 148**。全云树每题搜索一次，取全部末层保留轨迹，解对 **132 / 148**。与十份完整解相比，124 题两者都解对，仅树解对 8 题，仅完整解解对 6 题，两者都错 10 题。树净多解 2 题（+1.35 个百分点；按题重抽的描述性 95% 配对 bootstrap 区间 −3.38 至 +6.08），历史云端估价约为十份完整解的 **8.34 倍**。这不是等计算量实验，不能据此断言方法等效或树显著更优。

**如何确认同题。** 十个数字归档只含局部索引，没有题面。历史 Git 提交 `3cd916a973b934bf93023f2d82d78fe0f5369b91` 保留了十轮采集脚本、调用参数和任务加载器：它们运行 CoT 完整解基线，给生成器传入当题和空前缀，每次采集取旧提取题表的前 148 行。该快照 SHA-256 为 `a5904d5a779bd413546955d7d2ef4ba4ed417d05855404086f7fd6940b01b4c9`。旧 stdout 十段中的索引、两处回答记录、旧标记、改名记录、末条用量与数字档逐段唯一对应（1,480/1,480）；原文和配置不随结果发布。旧题表与树的 **444 个逐层输入**全部相符，对应现题库 Rank **100–199、500–547**，不是现 CSV 的同号 0–147。此配对靠归档与旧配方重建，不是逐请求输入、运行提交或服务端模型版本的证明。核对任一环失败即停止，不从答案反推题面。见[身份核验](<identity.py>)及[树核验](<tree_archive.py>)。

**判分。** “解对”指固定顺序中至少有一条通过验证，不是投票选出的最终答案。完整解按采集轮次 0 到 9 取前缀；只认最后一个非空行的单个四叶表达式，可带 `Answer:` / `Final Answer:`、可带 `= 24`，不从草稿里挑可行步骤。[表达式裁判](<answers.py>)使用 AST 白名单；两边都只准二元加减乘除，四数按重数恰用一次，**每个中间量均为非负整数，除法必须整除，终值须为 24**。这是限制版规则，不是允许分数或负中间值的标准 Game24 分数。树轨迹必须从实际四数合法走完三步，每步等式和剩余多重集均须吻合。不修复、不补全、不剔除无法解析的回答。完整解旧评分 1,480 槽全为零：旧入口用的是逐步轨迹检查器，不是最终表达式检查器。本次 760/1,480 份表达式、609/1,458 条末层轨迹通过，未过者都保留。若只查树的前 1 / 3 / 至多 10 条，覆盖 87 / 124 / 132 题；没有缩小树宽重跑。

**重复与预算。** 十轮解答序列无整轮复制；有 78 题出现完全相同的回答文本（5 题十份全同），1,480 个题–回答槽中有 311 个重复槽。760 份合法解按题和表达式结构只计 249 种（仅交换加、乘的左右子树，不作代数化简）。因此称为**完整解重复采样**，没有随机种子或缓存证据支持统计独立。树末层 144 题有十条、1 题九条、3 题三条；1,458 个所选文本均不同，但分支共享前沿。历史合并文件打乱了十列，另一个性能汇总只记最后一轮，均不作新的样本或十轮总账。表中调用、tokens、费用由逐轮累计计数作相邻差后加总；历史代码以元计，每百万输入 / 输出 tokens 按 1 / 2 元估价，与字段吻合，不是供应商账单或现价。逐角色账单、等宽重跑预算、可测端到端延迟及硬件能耗均缺失。

**复算。** 仓库根目录，Python 3.10+、本地 Git 历史和原归档。不连接模型或网络，不载入旧模型配置。测试的算术例子只检验裁判，不进入实验结果：
